# 章鱼 AI 全景分析

全网 AI 调研境内境外数据，由多个大模型混合部署。页面参考现代金融 App 截图风格，适合手机和微信竖版阅读：纯白背景、浅灰圆角卡片、黑色粗体标题、柠檬绿点缀与重点高亮（点阵矩阵与分段进度条点缀），所有内容保持紧凑的小字号和单列长页面结构。

## 快速预览

```bash
python3 server.py
# 打开 http://localhost:4173
```

也可以只预览静态页面：

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080
```

## 页面与推送内容

- 标题：**章鱼 AI 全景分析**
- 副标题：全网 AI 调研境内境外数据，由多个大模型混合部署。
- 竖版简报使用纯白背景、浅灰圆角卡片、黑色粗体标题和柠檬绿重点高亮，头部带分段进度条与点阵矩阵点缀。

- **开头「AI 每日总结」不再硬编码**：由 `analyze_brief()` 依据当日真实抓取标题动态计算，每次推送随数据更新。开篇板块给出四个观点：① 市场情绪（偏多/偏空/中性 + 情绪描述）② 多空博弈概率（多/空百分比 + 信号样本量）③ 利好板块 / 利差板块（按各板块净多、净空信号排序）④ 资金流向分析（净流入主线 + 遭回避方向）。
- **「AI 看盘」板块（紧跟「AI 每日总结」之后）**：按六维度内容策略用 AI 复盘最新的 **A 股、港股、美股** 行情，紧接开篇总结，打开简报先看行情。A 股——① 三大指数涨跌（上证/深成/创业板/科创50）② 两市成交额 ③ 涨跌家数与涨跌停 ④ 领涨 / 领跌板块 ⑤ 主力资金与北向资金 ⑥ 后市观点与策略。港股——恒生 / 恒生科技 / 国企指数、港股成交额、涨跌家数、领涨领跌、南向资金、后市观点。美股——道指 / 标普 / 纳指、美股成交额、涨跌家数、领涨领跌、资金与避险、后市观点。数据链路：东方财富公开行情接口（主源）优先抓取 → 腾讯证券行情接口（备用源）补位 → 内置真实快照兜底，无网络环境同样稳定出内容。详见 `docs/ashare_review.md`。
- **开头新增「AI 板块机会」板块**：与「AI 每日总结」共用同一套多空信号统计。「机会方向」按 信号强度 × 跨源热度 排序列出净多头板块 Top 4，每个板块给出净多计数、命中源数 / 提及条数，以及最多 3 条支撑新闻证据（标注来源数据源、方向相符的证据优先）；「承压方向」单列净空头板块 Top 2（每个最多 2 条证据）作为资金回避方向。当日样本无净多头信号时诚实标注「暂无净多头信号占优的板块」，不编造结论。
- **AI 内容的“双标的组合”统一改为港股现有 ETF**：「AI 情绪热力图」每个命中关键词和「AI 板块机会」每个方向均固定附 **2 个港交所现有 ETF（HKD 柜台）**，同时展示产品名称及其对应指数 / 参考标的。映射目录为 `sources._HK_ETF_CATALOG`，结构化字段为 `etf_pair[{code, name, benchmark, mapping, counters, counter_text}]`。AI、半导体、原油、黄金、美债、医药、智驾、地产、消费、东盟等使用对应主题产品；港股暂无纯光通信、纯白银 / 铂金 / 钯金、纯稀土或纯商业航天 ETF 时，文案明确标记“代理”，不伪造产品，也不再输出 A 股个股组合。**2026-10-20 补入 8 只港交所 ETF**：03143 马来西亚大型股、03599 港交所科技及美国科技 100、03569 韩国交易所半导体、03093 恒生港美机器人、03566 MSCI 全球战略金属精选、03585 全球未来科技、03197 全球战略资源、03438 恒生 AI 演进；分别接入东盟、光通信、半导体、智驾 / 机器人、贵金属、航天、地缘、AI 算力双标的，多柜台产品同时标注 HKD / CNY / USD 柜台（3599 / 3566 / 3585 / 3197），热力图卡片头部展示 `new_listings` 产品池。所有组合仅用于主题观察，不构成投资建议。完整口径见 `docs/hk_etf_pairs.md`。
- **「AI 政策分析」板块（在「AI 看盘」「AI 情绪热力图」之后）**：与「AI 每日总结」「AI 板块机会」共用同一批真实抓取标题，但按「政策维度」归因——① 货币政策 · 美联储 ② 央行 · 流动性 ③ 汇率与外汇干预 ④ 财政 · 关税与债务 ⑤ 产业与科技政策 ⑥ 资本市场监管 ⑦ 地缘与贸易政策 ⑧ 地产与地方政策。每个维度统计跨源命中数 / 提及条数与「政策净多 / 净空」，并用鹰派·鸽派词库判定政策取向（偏鹰 = 收紧、偏鸽 = 宽松；否定表述自动反转，例如「不再那么鸽派」计为鹰派），最多 2 条支撑新闻按同方向优先展示。当日样本无政策信号时如实标注「暂无政策面信号可统计」，不编造结论。引擎入口 `sources.analyze_policy()`，板块文案口径见 `docs/ai_policy_section.md`。
- **「AI 政策深度」「AI 政策研报」板块（政策分析之后、板块机会之前）**：「AI 政策深度」的主问题是**近 30 个自然日全球政策发布对股票市场的影响**（A 股 / 港股 / 美股）。只统计已核验发文日的发布、讲话信号和窗口内生效事项；同一主题同向只取最强贡献，避免同日组合拳把指数分乘三倍。**2026-10-28 起卡片分三层**：① 窗口内新发文（全额计分）② 发文在窗口之前、但影响期（每条政策自带的 `horizon`）今天仍在的「存量政策」（**半权**计入，逐条标已过天数 / 影响期至哪天 / 还剩多久）③ 窗口前段生效、现已到期的（**不计分**，只列名字）。这样窗口一滚动到 10 月、30 天内没有新发文时，卡片不会塌成一句「没有政策」——美联储加息、地产新政这些还在定价的政策继续给方向，但读者一眼能看出「这是存量余温，不是今日催化」；三市指数分同时给出「新发文 / 存量」两栏，每个市场再给一行「托底 / 拉低」（只列该市场得分绝对值 ≥0.2 的主线，最多各两条，由引擎生成 `driver_line` 字段，推送 / 页面 / 前端共用），另按主题归并出「主线」（方向 + 新 N / 存量 M + 合成分）；主线合成分 = 三市各自按组内规则算出的该主题得分之和，因此「各主线相加 = 三市指数分相加」，可对账。存量层的判定是「发文日 + `horizon` 仍覆盖窗口截止日」；影响期在窗口内走完的归「窗口内已到期」、在窗口开始前就走完的只在 `gap_note` 计数，都不计分。三层都没有时直接写「不外推方向」，不再出现「没有政策 + 机制推演」这种自相矛盾的说法。有公开收盘报道的标「已观测」（例如 2026-09-16 美联储加息后道指收跌约 600 点），其余标「机制推演」、不外推点位。窗口随运行日滚动，未核实日期的快讯不编成政策发布。引擎在 `policy_impact.py`，浅层接口 `GET /api/policy?deep=0` 也返回 `market_impact`。其后仍保留高级分析师对照层，共 7 项能力——① **政策法规知识库（RAG）**：央行报告、财政部文件、监管规章与境外央行决议共 18 条历史政策外掛为企业知识库（`sources._POLICY_KB`），解读新政策时先按「关键词 +2 / 维度匹配 +3 / 关键表述 +1.5」检索出关联历史政策与背景知识，再交由模型做同向 / 反向对比分析；② **分析师推理链**：模拟高级分析师把政策分步拆解为 宏观背景 → 行业限制 → 资金流向 → 受益板块（每步带证据与置信度），并自动生成**结构化政策影响研报**（结论评级 + 长远冲击评估：结构性 vs 周期性 + 时间尺度 + 传导路径）与**思维导图**；③ **金融术语口径**：用政策术语库对「稳健 / 适度宽松 / 从严 / 严禁」等修饰词做经济学 + 法学双维解读（强度 -3…+3），比通用词频更贴近市场含义；④ **政策舆情情感打分**：政策发布后的新闻舆情与官媒解读按 正向 / 中性 / 负向 即时打分；⑤ **政策窗口期**：分开统计「官媒口径」与「市场化解读」，情绪差 ≥ 0.3 判定为预期差窗口（统计信号，不构成投资建议）；⑥ **政策传导图谱**：政策主体 → 受影响行业 → 产业链上下游节点连成一张图；⑦ **时序模型**：**LSTM**（纯 Python 单层 + BPTT 训练，捕捉非线性与长期依赖，评估重大政策后的中长期走势节奏与政策情景偏移）+ **Prophet 式加性分解**（趋势 + 季节性 + 政策突变哑变量的岭回归，剥离季节后度量政策窗口期的中期波动，政策效应给出回归与事件研究两套口径）。模型输入序列复用推送路径抓到的日 K，离线时回退明确标注的合成演示序列；样本不足时如实标注「不外推 / 不可辨识」。推送与页面呈现时「AI 政策」总结压为一句话；深度卡片只展示政策条目元数据与标题，不展示关键表述、背景摘要、历史市场含义或逐条历史对比；「政策术语口径（修饰词解读）」只保留一条加权强度与方向汇总句。板块口径与实现细节见 `docs/ai_policy_section.md`，实时结果见 `GET /api/policy`（`?deep=0` 只要基础统计）。
- **政策数据的源头与新鲜度（2026-10-28 起）**：台账是人工核过的发文，窗口一滚动就会变空（2026-10-28 时窗口内 0 条、最近一条 09-20），所以「AI 政策深度」另开两条通道：① **官方源抓取**——`policy_impact.OFFICIAL_SOURCES` 登记 11 个机构入口，美联储 / 欧洲央行 / 日本央行 / 美国财政部抓列表页（`html`），中国政府网 / 人民银行 / 证监会 / 住建部 / 金融监管总局 / 财政部 / 发改委只登记入口（`manual`，不臆造深层文件链接）；逐源给状态 `ok` / `empty` / `error`（附异常）/ `manual`，抓到的条目只列**不计分**（方向待标注），与台账同日同维度或标题重合的去重。② **当日官方源动态**——现有新闻管线里来自官方源的标题标「待核验发文」，快讯日期不等于发文日，故不入台账也不计分。抓取结果落 `policy_ledger_cache.json`（TTL 36 小时，过期即弃，宁可显示「尚未抓取」也不拿旧条目冒充今天），`python3 policy_impact.py --refresh --write` 手动刷新，`--render-index` 重生成静态页政策段，`.github/workflows/policy-ledger.yml` 每日 09:10（北京时间）自动跑并把缓存与页面提交回 main。台账 11 条全部挂官方入口并标 `官方原文 / 媒体转述`（当前 11 条引用均为媒体转述，卡片照写，`--verify` 可逐条核对）。页面只显示一行数字（入口数、抓通 / 空 / 失败 / 仅入口、抓取时间 UTC、台账来源构成、失败源名单），不写操作提示。见 `docs/ai_policy_section.md` 〇.六。
- **新增「大 V 分析」栏目（在「AI 板块机会」之后、「全网快讯」之前）**：以公开的「预测历史」（Predictive History）框架为蓝本，用 AI 对**近期政治 / 地缘 / 经济**做结构化逻辑推导。只借鉴可验证方法——① 划定参与者与周期 ② 识别选举 / 安全 / 资本等激励 ③ 核算后勤、能源咽喉、债务、利率和制度约束 ④ 展开低成本骚扰 vs 高价防御的升级博弈 ⑤ 用西西里远征等历史类比提出可检验假设 ⑥ 给出基准 / 升级 / 缓和情景和证伪信号。引擎在 `big_v_analysis.py`，`sources.analyze_big_v()` 包装后进入 `analyze_brief()`、`build_html()` 和 `GET /api/big-v`（兼容 `/api/bigv`）；页面静态快照为 2026-10-26，服务运行时按当日真实抓取标题重算。**这是 AI 框架仿推演，不模仿本人语气，不代表其本人观点或背书；不采用不可证伪的末世论 / 秘密组织叙事，情景关注度不是统计概率或投资建议。** 完整口径、公开资料与当期推导见 `docs/big_v_analysis.md`。

- **正文最后的「全网快讯」列表（已隐藏）**：2026-10-27 起按需求在推送与页面里**不再展示**这张卡片（开关 `sources.NEWS_CARD_ENABLED = False`，改回 `True` 即恢复）。原始快讯照旧全部抓取，「AI 每日总结 / 看盘 / 情绪热力图 / 政策分析 / 板块机会 / 大 V 分析 / 量化日报」仍用它们统计信号，只是不再把当日标题流水铺在正文末尾。卡片本身的分组、跨源去重、标题转义、随字符额度收敛（3 → 2 → 1 → 省略）逻辑与回归用例都保留，重新打开即生效。

## 数据与推送

**结构化分析接口**：`GET /api/brief` 返回当日抓取原始标题；`GET /api/heatmap`、`GET /api/policy`、`GET /api/big-v`（兼容 `/api/bigv`）、`GET /api/quant`、`GET /api/radar`（兼容 `/api/indie-radar`，`?format=prompt` 返回当日「AI 提」提示词）分别返回关键词情绪、政策统计 / 深度层、「大 V 分析」的政治 / 地缘 / 经济框架推演、「AI 量化日报」的五维分析 / 策略信号 / 风险 / 41 个原子动作方案，以及「AI 独立开发雷达」的 7 模块 + 心法。前五个接口共用同一份 5 分钟快讯抓取缓存（雷达采集的是 19 个独立开发 / 产品信号源，自带 30 分钟缓存，不占用快讯缓存），页面与推送使用同一批证据；量化日报另外用 `--input` 接收 Agent 侧工具返回的数据包（财报、一致预期、两融、龙虎榜、大类资产、因子收益、基差），缺项自动标「数据暂缺」。

**推送内容默认按 PushPlus 10 万字上限口径生成**（由 `sources.pushplus_quota()` 统一决定字符上限与每源条数，`build_html()` 自动遵守）。配置 `PUSHPLUS_TOKEN` 后，可通过 GitHub Actions 或本地服务执行推送：

```bash
PUSHPLUS_TOKEN=xxx python3 push_brief.py
```

**推送默认一对一**：消息只发给 `PUSHPLUS_TOKEN` 所属账号自己，载荷不带群组编码（`topic`），无需改工作流。需要一对多群组推送时，显式设 `PUSHPLUS_TOPIC=oai.1`（群成员扫码入群后均可收到）：本地运行为 `PUSHPLUS_TOPIC=oai.1 python3 push_brief.py`，GitHub Actions 则在 `daily-push.yml` 的推送步骤 `env:` 下加 `PUSHPLUS_TOPIC: oai.1`。本地服务 `POST /api/run` 同样遵循该规则。

**推送前大盘数据新鲜度检查（不是最新就不推）**：推送前会先确认简报里的「AI 看盘」A 股数据为最新——①行情接口可用（东方财富主源与腾讯证券备用源至少一个可用）；②接口数据不滞后（最新日 K 不早于内置快照基线）；③复盘数据来自实时接口（东方财富或腾讯证券备用源，非内置快照兜底）且复盘日等于最近一个可复盘交易日。任何一条不满足即放弃本次推送：`push_brief.py` 退出码 3（GitHub Actions 显示为失败，便于发现行情源异常），本地服务 `POST /api/run` 返回 409 并透出具体原因。页面「AI 看盘」标题右侧的标签实时展示该检查结果（`GET /api/market`）。

**推送前敏感词检测（违规内容不推）**：对齐《网络安全法》《互联网信息服务管理办法》《网络信息内容生态治理规定》第六条。`sensitive.py` 先按条剔除违规快讯再生成 HTML，再扫描标题 + 正文；残留命中则放弃本次推送：`push_brief.py` 退出码 4，本地服务 `POST /api/run` 返回 422。词库只覆盖法规列明的违法 / 不良信息类别，**不**编造政治人物名单，也**不**把战争、制裁、Iran、立案、骗局、Ponzi、Terrorism Risk Insurance、Drug Transit、博彩股、六合彩等正常财经 / 地缘 / 监管新闻当违规。执法、驳斥口径（打击 / 查处 / 反对 / charges）视为报道放行。排障接口 `GET /api/sensitive`。详见 `docs/sensitive_filter.md`。

**推送前「去 AI 味」体检 + 改写，分两层**：
- **设计 / 排版层（Hallmark 闸门）**：用 GitHub 上的 [`Nutlope/hallmark`](https://github.com/Nutlope/hallmark)（MIT）反 AI-slop 设计规则的静态子集，扫描并改掉推送 HTML 里的装饰痕迹（眉标、`✦` 装饰图标、追踪大写、中点元信息、单斜体词、缺焦点环等），只改装饰层、锁住数字 / 日期 / 人名 / 引用 / 链接，签名漂移会整体回滚。
- **文本内容层（Humanizer-zh 闸门）**：用 [`op7418/Humanizer-zh`](https://github.com/op7418/Humanizer-zh)、[`blader/humanizer`](https://github.com/blader/humanizer) 与 [`jiji262/humanizer-chinese`](https://github.com/jiji262/humanizer-chinese)（均 MIT）的 18 条静态可判定模式扫描推送 HTML 与管理页的**文字内容**，删除零信息纯套话（升华结尾、客服腔、假互动、讲义腔路标词）。检测要宽、改写要窄：假对比 / 三段式 / 意义拔高等需语义判断的模式**只报告不改写**；逐字新闻标题、证据行、数字、日期、引号原话与链接全部受保护；事实签名漂移整体回滚。明确排除 MIT + Non-Commercial 的 `swaylq/humanize-chinese`，不引入其代码或词表。

两层闸门依次插在大盘新鲜度与敏感词快讯过滤之后、敏感词终检与实际 POST 之前；默认均 `polish`（非阻塞），只有 `DEAI_STRICT=1` / `HUMANIZER_STRICT=1` 且有残留强信号才拦截（`push_brief.py` 退出码 5 / 6，`POST /api/run` 返回 422）。`GET /api/hallmark`（别名 `/api/deai`）与 `GET /api/humanizer`（别名 `/api/text-deai`）分别对**推送 HTML 与管理页各出一份体检报告**（`?surface=push|page|all`）；管理页两个可视化区展示两面分数、命中模式、保留项与方法边界，并可切换本次推送模式（`POST /api/run` body 的 `deai_mode` / `humanizer_mode`）。GitHub Pages 静态托管时两区保留快照文案、不发请求。详见 `docs/hallmark_deai.md` 与 `docs/humanizer_zh.md`。

相关环境变量（推送容量 / 测试 / 应急）：

- `PUSHPLUS_MEMBER=0`：**推送容量口径**。默认即按 PushPlus 会员的 **10 万字** 上限生成（留 2,000 字符安全余量 → 98,000 字符，每个数据源最多 20 条）；普通/实名账号（2 万字上限）显式设为 `0` 即退回精选口径（19,500 字符 · 每源 3 条）。
- `PUSHPLUS_TOPIC=oai.1`：**推送模式**。默认**留空 = 一对一**（只发给 token 所属账号自己）；显式填群组编码才切回一对多群组推送（GitHub Actions 需在 `daily-push.yml` 的 `env:` 下加这一行，仓库 Secrets 里存值也可以）。
- `PUSHPLUS_MAX_CHARS=98000`：自定义单条推送字符上限（覆盖上面的会员/普通默认值；超上限时自动逐级收敛每源条数，保证发得出去）。
- `PUSHPLUS_ITEMS_PER_SOURCE=20`：推送口径里每个数据源最多展示条数（`all` = 抓到的全部快讯）。注意：「全网快讯」卡片当前已隐藏（`sources.NEWS_CARD_ENABLED = False`），该变量只影响抓取与分析口径；把开关打开后，卡片固定按 **每源 3 条** 输出（`sources.NEWS_ITEMS_PER_SOURCE`），且只能往下压（如设 `1` 即每源 1 条）。
- `BRIEF_FETCH_LIMIT=20`：自定义每个数据源的抓取条数（默认与展示口径一致，避免「额度放宽了但内容没变多」）。
- `BRIEF_FETCH_WORKERS=8`：并发抓取线程数（69 个源互不依赖，默认 8 线程；设 `1` 退回串行）。
- `SKIP_MARKET_CHECK=1`：跳过新鲜度检查，直接推送。
- `MARKET_FRESHNESS_FORCE=fresh|stale`：强制检查结果，用于联调测试。
- `SKIP_SENSITIVE_CHECK=1`：跳过敏感词检测（测试 / 应急，不建议日常开启）。
- `SENSITIVE_FORCE=pass|block`：强制敏感词闸门结果，用于联调测试。
- `SENSITIVE_LEXICON=/path/to.txt`：外掛敏感词（一行一词；`block:词` 为高严重度）。
- `DEAI_MODE=polish`：推送前「去 AI 味」闸门模式。`polish`（默认）体检 + 自动改写装饰层；`audit` 只体检不改写；`off` 跳过。前端下拉框的选择通过 `POST /api/run` 的 `deai_mode` 临时覆盖。
- `SKIP_DEAI_CHECK=1`：跳过去 AI 味闸门（测试 / 应急）。
- `DEAI_FORCE=pass|block`：强制去 AI 味闸门放行 / 拦截（测试 / 应急，优先于严格模式）。
- `DEAI_STRICT=1`：改写后仍有未修复的 Floor 命中就拦截推送；默认关闭（去 AI 味是设计体检，不是合规闸门）。
- `HUMANIZER_MODE=polish`：**推送前「文本内容去 AI 味」闸门**（规则取自 GitHub 上的 [`op7418/Humanizer-zh`](https://github.com/op7418/Humanizer-zh)、[`blader/humanizer`](https://github.com/blader/humanizer)、[`jiji262/humanizer-chinese`](https://github.com/jiji262/humanizer-chinese)，均 MIT）。`polish`（默认）体检 + 删除零信息纯套话；`audit` 只体检；`off` 跳过。前端选择通过 `POST /api/run` body 的 `humanizer_mode` 临时覆盖。
- `SKIP_HUMANIZER_CHECK=1`：跳过文本内容去 AI 味闸门（测试 / 应急）。
- `HUMANIZER_FORCE=pass|block`：强制文本层闸门放行 / 拦截（测试 / 应急）。
- `HUMANIZER_STRICT=1`：清理后仍有 `strong` 强信号命中就拦截推送（退出码 6 / HTTP 422）；默认关闭。
- `QUANT_HOLIDAYS=2026-02-16,2026-02-17,...`：**量化日报的休市日历**。交易日判定只用「周末 + 固定公历休市日（1/1、5/1-5/3、10/1-10/7）」，春节 / 清明 / 端午 / 中秋这类农历假期不猜，用这个变量（或 `quant_daily.py --holidays`）补进来；非交易日跑日报会输出「今日非交易日，无日报」并以退出码 3 结束。
- `DEEPSEEK_API_KEY=sk-...`：**全部搜索切换到 DeepSeek Search API**（2026-10-17 开放自研搜索，`POST /v1/tools/search`，$0.75/千次成功请求、空结果免费、5 QPS）。仓库里原先经 Google News RSS 检索的 11 个源（10 个财经社区 + Reuters）与「Google news 中文」在配置后优先用 DeepSeek（`site: / lang: / after:` 算子），未配置 / 失败 / 空结果自动回退原 RSS 通道；页面底部新增「全网搜索」卡片（`GET /api/search`），另有 `GET /api/deepseek/status` 自检与 `GET|POST /api/fetch` 单页抓取（Fetch API）。GitHub Actions 加同名 Secret 即启用。配套变量：`DEEPSEEK_SEARCH_ENABLED=0`（显式禁用）、`DEEPSEEK_API_BASE_URL`（覆盖端点地址）、`DEEPSEEK_NEWS_QUERY`（覆盖中文新闻源检索词）。接入细节与成本口径见 `docs/deepseek_search.md`。
